# 知识库语料

`corpus/` 中的 Markdown 是知识库问答的检索语料。`kb-index.json` 由 `pnpm kb:ingest` 根据语料生成，会打包进服务端。修改语料后需要重新生成；`tests/knowledge-rag.test.ts` 会检查索引是否与语料一致。

## 转换方法

```bash
pdftotext <原文>.pdf <原文>.txt     # poppler-utils 24.02
python3 scripts/kb_pdf_to_markdown.py <原文>.txt knowledge/corpus/<id>.md '<元数据 JSON>'
pnpm kb:ingest
```

转换只做排版处理：合并 PDF 硬换行，去掉页码、封面和目录，去掉中文与数字之间多余的空格，并为章、节加上 Markdown 标题。条文内容不做改写。引用前请以原文 PDF 为准。

## 元数据字段

每个文件的 front matter 包含以下字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 文件唯一标识，同时作为引用 ID 的前缀 |
| `title` | 是 | 文件名称 |
| `docNo` | | 文号 |
| `issuer` | | 发文机关 |
| `region` | | 适用地区，全国性规则填“全国” |
| `issuedAt` | | 印发日期，`YYYY-MM-DD` |
| `effectiveFrom` | | 施行日期，`YYYY-MM-DD` |
| `effectiveUntil` | | 有效期截止日期，`YYYY-MM-DD` |
| `validity` | | 原文中关于施行和有效期的表述 |
| `sourceUrl` | | 原文页面 |
| `attachmentUrl` | | 原文 PDF |

问答时会按北京时间的当天日期计算每份文件的状态：有效期内、已过有效期或尚未施行。

添加自有文件时，按同样的格式放进 `corpus/`，然后运行 `pnpm kb:ingest`。语料较大或不宜打包时，可以把生成的索引放在服务器上，并用 `KB_INDEX_PATH` 指定路径。
